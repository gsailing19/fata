## 结论

v3 架构方向正确，安全模型比旧版明显改善，但当前生产主流程存在多个断链：真实用户很可能因 PoW 难度不一致无法提交；即使提交成功，匹配后也不会关闭 Issue 或发送通知；撤回和邮件通知的实现也均未真正接通。当前产品处于“页面可访问、核心链路未闭环”的状态。

## 发现

### F-01 [P0] PoW 难度不一致，真实提交大概率失败

- 文件/行号：`config/worker.js:507` 下发 `difficulty=14`；`config/worker.js:526` 校验 `powDifficulty=16`；`modules/pow-solver.js:31` 按服务端下发难度求解。
- 现状：浏览器只求 14 个前导零位，Worker 要求 16 位，`/api/challenge` 大概率返回 `pow_invalid`。
- 影响：真实用户无法拿到 submit token，无法进入匹配池；与审计中 `submit_success=0` 吻合。
- 建议：统一难度来源，改为单一常量或由 Worker 在同一个函数内生成并校验。

### F-02 [P0] 匹配成功后不关闭 Issue、不创建 Match Issue、不发通知

- 文件/行号：`config/worker.js:582`（`handleSubmit`）、`config/worker.js:765`（返回 matchInfo）、`index.html:1491`（只展示成功页）。
- 现状：`/api/submit` 自动匹配后直接返回对方邮箱；前端只调用 `showMatchSuccess`。`closeMatchedIssues()`（`index.html:1641`）和 `/api/close-match`（`config/worker.js:1071`）均未被调用。
- 影响：匹配池不清理、Match Issue 不创建、另一方永远收不到通知。

### F-03 [P0] `handleCloseMatch` 邮件逻辑发错收件人

- 文件/行号：`config/worker.js:1116` 解密 `matchedIssueNumber` 的邮箱，`config/worker.js:1139` 发给这个邮箱，`config/worker.js:1141` 又让对方“联系这个邮箱”。
- 现状：即使 close-match 被调用，匹配对象会收到一封写着自己邮箱的邮件，且只有一方被通知。
- 建议：解密双方邮箱，分别发送两封独立邮件，内容指向对方邮箱。

### F-04 [P1] 用户撤回被 token 只读代理拒绝

- 文件/行号：`config/worker.js:282`（非 GET + 非 HMAC 返回 403）、`index.html:1593`（token PATCH 关闭 Issue）。
- 现状：前端撤回走 `/api/github/issues/{n}` PATCH，被代理拒绝；Worker 已有 `/api/withdraw`（`config/worker.js:1207`）但前端未使用。
- 影响：回访用户无法撤回 pending 文字。

### F-05 [P1] E2E 绕过真实 `/api/submit` 链路

- 文件/行号：`tools/e2e-test.js:296` 手动关闭 Issue，`:300` 手动创建 Match Issue，`:329` 手动触发 Resend。
- 现状：E2E 没有调用 `/api/submit`、`/api/challenge`、`/api/close-match`，因此 F-01 到 F-04 全部可以“通过测试”。
- 建议：重写 E2E，用测试标记走真实用户路径，并断言 Issue 关闭、Match Issue、双方通知。

### F-06 [P1] Worker 源码不在 git 版本管理中

- 文件/行号：`.gitignore:12`、`.gitignore:15`；`git ls-files config/worker.js` 为 0。
- 影响：无法追溯、无法回滚，生产代码与仓库脱节。
- 建议：建立私有备份仓库或受保护的内部 git 分支；快照目录不公开。

### F-07 [P1] 旧 `_kv<=3` 数据兼容路径存在隐私回退

- 文件/行号：`config/worker.js:1695` 使用公开 `issueBody.text_snippet` 参与评分，`config/worker.js:1721` 解密旧 Issue body 中的加密邮箱。
- 现状：新数据 `_kv4` 已做到“GitHub 只存元数据”，但匹配引擎仍兼容旧 Issue body 中的明文 snippet 和加密字段。
- 影响：历史公开 Issue 若仍包含用户明文片段，会违背“GitHub 无敏感数据”的对外表述。
- 建议：盘点现有 Issue 的 `_kv` 分布，迁移或关闭旧数据，再移除兼容路径。

### F-08 [P2] Resend 发送前未检查退订

- 文件/行号：`ideas-todo.md:33`、`config/worker.js:921`。
- 影响：用户点了退订后仍可能收到通知。

### F-09 [P2] beacon 漏斗与 Cloudflare PV 偏差过大

- 证据：`tools/audit-logs/audit-latest.log:47` 显示 1 次 `page_view`，`:48` 显示 Cloudflare 73 PV。
- 影响：无法用现有 funnel 判断真实转化，可能掩盖主流程不可用。

### F-10 [P2] 旧模块残留与新架构不一致

- 文件/行号：`modules/match-engine.js:79`、`modules/resend-retry.js:26`、`modules/resend-retry.js:231`。
- 影响：代码阅读者会误以为仍在使用 `worker.fata.uk` 和 `HMAC_KEY_RAW`。

### F-11 [P3] 算法配置存在死代码

- 文件/行号：`ideas-todo.md:36`；`config/algorithm-config.json` 中 `max_match_count=5` 未被使用。
